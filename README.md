# D SMART ERP v2.0 · Enterprise redesign

기존 업무 로직을 보존한 SAP·더존 스타일 기업용 화면 리디자인입니다.

## 실행

프로젝트 폴더에서 다음을 실행한 뒤 http://127.0.0.1:8080 을 여세요.

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

별도 앱 빌드나 npm 설치는 필요하지 않습니다. index.html 직접 열기도 가능하지만, 데이터 저장 origin이 일정한 로컬 서버 실행을 권장합니다. 기존 데이터는 기존 시스템관리에서 JSON 백업 후 새 화면의 시스템관리에서 복원하세요. 다른 브라우저·포트·주소의 localStorage는 자동으로 공유되지 않습니다.

## 검증 재실행 (선택)

Node.js 24.15 이상(24.x), 22.22.2 이상(22.x) 또는 26 이상이 필요합니다. 개발 테스트에만 jsdom을 사용합니다.

```sh
npm install
npm test
```

결과는 qa/regression-rerun.json에 생성됩니다. 테스트는 메모리 DOM의 별도 저장소에서 실행되어 실제 브라우저 데이터를 수정하지 않습니다. 원본 비교는 원본을 별도 폴더에 풀고 ORIGINAL_ROOT에 그 경로를 지정해 `node tests/regression.cjs --baseline`으로 실행할 수 있습니다.

## 포함 자료

- docs/ANALYSIS-AND-TESTS.ko.md: 구조·업무·데이터·변경점·검증·원본 제약 분석
- qa/: 원본/수정본 자동 테스트 및 브라우저 메뉴 테스트 결과, 파일 해시
- tests/regression.cjs: 기존 기능 19개 회귀 시나리오
- tests/operations.cjs: 운영 기능 33개 검증 시나리오
- 데스크톱 및 모바일 미리보기 이미지는 별도로 제공한 전체 프로젝트 ZIP에 포함되어 있습니다.

기존 erp-01.js~erp-11.js 및 저장 키를 보존하고, 신규 업무 데이터는 operations 필드에 추가했습니다. 구매·판매·결재·분석 화면은 새 업무 흐름으로 연결했습니다. 대시보드 중복 DOM은 렌더러 호환을 위해 숨김 컨테이너에 보존되어 있습니다. 날짜 제한과 일부 고정 예시는 원본 그대로입니다. GitHub 반영 대상은 `ODH-dev/D-SMART-ERP`의 `v2-development-from-main` 브랜치이며, main 브랜치는 변경 대상에서 제외합니다.

## 업무 기능 확장

- 내 업무: 승인 대기, 입출고 대기, 납기 지연, 담당 전표를 클릭해 목록으로 이동합니다.
- 전표 상세: 고유 번호, 담당자, 거래처, 품목, 금액, 첨부 다운로드, 출력과 처리 이력을 제공합니다.
- 승인: 작성 → 승인 요청 → 승인/반려 → 입출고 → 마감. 상태 및 선택 역할에 따라 버튼과 처리를 제한합니다.
- 취소·정정: 사유를 기록하고 원본을 보존합니다. 입출고 취소는 반대 원장으로 재고를 복구하며 정정 전표가 원본을 참조합니다.
- 현장 분석: 현재 현장 재고, 예산, 기초 집행, 실제 등록 비용 및 기간별 비용을 집계합니다.

신규 전표·현장 사용은 현재 날짜로 작성할 수 있습니다. 원래 입출고 화면의 날짜 제한은 유지됩니다. 기존 완료 전표는 원장 추적 정보가 없어 자동 취소가 차단되며, 적용 이후 처리된 전표부터 반대 원장을 생성합니다. 첨부는 5개, 파일당 500KB 이내이며 전체 브라우저 저장 용량의 제한을 받습니다. 기존 JSON 백업에 새 업무 데이터도 포함됩니다.

업무 역할은 현재 브라우저에서 선택하는 기능입니다. 서버 로그인·사용자 권한 검증·여러 사용자 간 공유 DB는 포함하지 않습니다. 변경 이력도 브라우저에 저장되어 서버 감사 로그의 위변조 방지 성질을 제공하지 않습니다. 기존 기록의 과거 승인자나 이력은 임의 생성하지 않습니다.

검증 결과: 기존 기능 19개와 업무 기능 33개, 총 52개 자동 검증 통과. 전표 상세 및 현장 분석 화면을 실제 브라우저에서 확인했습니다. 최신 결과는 qa/regression-rerun.json과 qa/operations-results.json을 참고하세요. 과거 QA 자료는 이전 버전의 기록입니다.
