# D SMART ERP v2.0 리디자인 분석 및 검증 보고서

작성일: 2026-10-21 (Asia/Seoul)

## 결과

SAP Fiori의 명확하고 일관된 업무 화면과 더존의 통합 업무 구성을 참고한 네이비·블루 기업용 UI를 적용했습니다. 외부 제품의 로고나 UI 코드를 복제하지 않았습니다. 기존 22개 메뉴 및 11개 ERP 업무 JavaScript를 보존했습니다. 별도 프레임워크나 서버 데이터베이스로 전환하지 않았습니다.

## 프로젝트 전체 구조 분석

빌드 없는 HTML/CSS/JavaScript 정적 프로젝트입니다. index.html이 erp-01.js부터 erp-11.js, dashboard-v2.js를 순차 실행합니다. 각 버전은 전역 render/showPage 함수를 감싸 기능을 추가합니다. 순서가 바뀌거나 과거 DOM ID가 사라지면 후속 기능이 깨질 수 있으므로 원본 스크립트 순서를 유지했습니다.

## 업무 기능 지도

- 대시보드: 4개 핵심 지표, 5개 보조 지표, 월별 거래, 부족 재고, 발주, 예산, 최근 입출고.
- 재고·입출고·원자재: 제품 등록·수정·삭제 제약, 검색·상태 필터, 수량 검증, 안전재고.
- 창고·통합 물류: 위치별 재고, 창고/현장 이동, 구매요청, 승인 후 입고, 현장 사용과 비용 반영.
- 구매·매입매출: 발주/판매 등록, 변경·삭제, 입고·출고 처리 및 재고 연동.
- 생산·영업·거래처·인사·업무·문서·현장·안전: 원본 등록/수정/삭제 화면과 상세 운영 예시 유지.
- 전자결재·예산·경영분석·분석 리포트·알림: 원본 시연 결재, 비용, 분석 및 상태 표시 유지.
- 시스템관리: JSON 백업·복원 및 시연 데이터 초기화 유지.

## 저장 구조와 호환성

기본 키는 `d-smart-erp-v1`, 시연 날짜 마이그레이션 키는 `d-smart-erp-demo-dates-2024-v1`입니다. products, movements, locationStocks, locationTransfers, portfolioModules 및 erp19 하위 구조를 변경하지 않았습니다. 새 UI 어댑터는 데이터 및 localStorage에 쓰지 않습니다. 원본 erp-01~11의 초기화·마이그레이션 동작은 그대로 실행됩니다.

localStorage는 브라우저와 origin(프로토콜·호스트·포트)에 종속됩니다. 다른 폴더/file URL이나 새 서버 주소로 옮길 때 자동으로 데이터를 공유하지 않을 수 있습니다. 기존 화면 시스템관리에서 JSON을 내려받고 새 화면에서 복원하세요. 프로젝트 ZIP에는 사용자의 실제 브라우저 저장 데이터가 포함되지 않습니다.

## 중복 대시보드 통합 방식

화면에는 v2 통합 대시보드만 중심으로 표시합니다. 중복 전체 재고, 구형 미입고 카드 및 구형 부족재고 표는 숨겨진 legacyDashboardBindings 컨테이너로 옮겼습니다. DOM 자체를 삭제하지 않아 erp-01/08/09/11의 기존 렌더러 참조를 보존합니다. 전체 등록 품목·누적 입고·누적 출고·진행중 업무·통합 알림은 보조 카드로 재배치했습니다. 최근 입출고 표도 한 번만 표시합니다. 통합 대시보드는 기존 render 호출과 메뉴 복귀 시 최신 데이터를 반영합니다.

## 디자인 변경

네이비 업무 내비게이션, 브랜드 마크, 메뉴 검색, 로컬 저장 상태, 일관된 페이지 헤더를 구성했습니다. 표 중심의 업무 화면에 얇은 테두리·통일된 여백·작은 모서리·명확한 숫자 계층을 적용했습니다. 핵심 지표와 보조 지표를 구분하고 6개월 차트를 압축했습니다. 좁은 화면에서 메뉴 줄바꿈, 카드 재배열, 표 내부 스크롤을 적용했습니다. 키보드 포커스, 본문 바로가기, 입력 접근성 이름과 인쇄 스타일을 추가했습니다.

## 검증 결과와 한계

원본 공통 DOM 회귀 테스트 20/20, 수정본 24/24 통과. 실제 앱 스크립트와 폼 이벤트를 JSDOM에서 실행했으며 별도 테스트 저장소를 사용했습니다. 브라우저에서는 전체 22개 메뉴를 클릭하고 화면 활성 상태를 검사했으며 콘솔 오류가 없었습니다. 대시보드·재고 화면을 시각 검토했고, 390×844 모바일 화면에서 문서 가로 넘침이 없는 것을 확인했습니다.

자동 회귀의 JSON 백업은 Blob/다운로드 링크 생성을 검사하며 OS 다운로드 저장창을 검증하지 않습니다. 복원 테스트는 기존 형식의 가상 파일을 입력해 처리 경로와 저장 결과를 검사했습니다. 브라우저 시각 검증은 전 메뉴의 모든 입력 조합, 모든 장치, 모든 장애 조건을 보증하지 않습니다. JSDOM 검증은 레이아웃 검증을 대체하지 않습니다. 테스트 상세는 qa/ 폴더를 확인하세요.

## 유지한 원본 제약과 후속 과제

이번 작업은 기업용 UI 리디자인입니다. 서버 인증·다중 사용자 동시성·권한 통제·회계 법정 기능을 새로 구현하지 않았습니다. 전자결재는 기존 관리자 시연 방식입니다. 입력 날짜의 2023-01-01~2024-10-31 제한과 2024-10-18 시연 기준을 유지했습니다. erp-10의 일부 운영 지표와 표는 고정 예시이며 실제 등록 데이터와 별도로 표시됩니다. 예산의 baseline도 시연 기준금액입니다.

원본은 최초 실행 시 샘플 품목을 채우고 특정 조건에서 날짜 마이그레이션/기본 샘플 교체를 수행합니다. 실제 업무 데이터 운영을 준비한다면 별도 범위에서 시연 초기화 분리, 스키마 버전 관리, 서버 저장·인증·트랜잭션·감사 로그를 설계해야 합니다. 이 보고서에서는 원본 동작을 변경했다고 주장하지 않습니다.
